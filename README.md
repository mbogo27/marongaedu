# Maronga Dental Academy — v2 (Full Platform)

A dental e-learning e-commerce platform for Dr. Godfrey Maronga, built per
`spec-2.md`. Real accounts, real persistence (SQLite), real learner
progress/certificates, and a full admin back-office. **Payments, email/SMS,
and Google OAuth are simulated stubs** — no real gateway or provider is
ever called (see `spec-2.md` §6 for the exact simulation rules).

> v1 (the earlier no-backend marketing demo) is preserved at git tag
> `v1-marketing-demo` / branch `main`. This is `v2-ecommerce`.

## Stack

- **Framework:** Next.js 16 (App Router, Turbopack)
- **DB:** SQLite via Prisma 7 (driver-adapter model — see `prisma.config.ts` / `src/lib/db.ts`)
- **Auth:** custom — bcrypt password hashing, `jose`-signed httpOnly session cookie + DB-backed `Session` table, `src/lib/dal.ts` as the authorization boundary, `proxy.ts` for optimistic redirects
- **Rich text:** TipTap (course descriptions, reading lessons)
- **Drag-reorder:** `@dnd-kit` (course editor module reordering)
- **Charts:** Recharts (admin dashboard)
- **PDF:** `pdf-lib` (certificates, invoices)
- **Video:** local HTML5 `<video>` — a pool of 10 placeholder clips generated by `scripts/generate-placeholder-videos.mjs` (ffmpeg), swap for real footage later

## Setup

```bash
npm install          # also runs `prisma generate` via postinstall
cp .env.example .env # defaults work as-is for local dev
npm run db:push       # create prisma/dev.db from the schema
npm run db:seed       # populate demo data (courses, users, coupons, ...)
npm run dev
```

Open http://localhost:3000. Placeholder lesson videos already exist in
`public/videos/` and `public/captions/` (committed) — re-run
`node scripts/generate-placeholder-videos.mjs` any time to regenerate them
(requires `ffmpeg` on PATH).

To wipe and reseed at any point: `npm run db:reset`.

Every other seeded user (`student1@demo.co.ke` … `student15@demo.co.ke`,
used to populate charts/reviews) shares the same password.

Coupons: `WELCOME10` (10% off everything), `STUDENT500` (KES 500 off the
first three seeded courses), `EXPIRED` (past its validity window, to
demo the failure state).

Payment stub triggers (checkout page, per `spec-2.md` §6):
- M-Pesa number ending `0000` → fails. Ending `1111` → stays pending
  (shows a Cancel button). Anything else → succeeds.
- Card number ending `0000` → declined. Ending `0002` → insufficient
  funds. Anything else (Luhn-valid) → succeeds.

## Environment variables

See `.env.example`. `DATABASE_URL` is a `file:` path relative to the
project root (Prisma 7's driver-adapter model resolves it from
`process.cwd()`, not from the schema file's directory — see
`src/lib/db.ts`). `SESSION_SECRET` signs session cookies; generate a real
one for anything beyond local dev with `openssl rand -base64 32`.

## Project structure

- `prisma/schema.prisma` — full data model (users, courses, modules,
  lessons, quizzes, enrollments, progress, payments, coupons, reviews,
  certificates, settings, ...)
- `prisma/seed.ts` + `prisma/seed-data.ts` — demo data
- `src/lib/dal.ts`, `src/lib/session.ts`, `proxy.ts` — auth
- `src/lib/actions/**` — server actions (learner-facing), `src/lib/actions/admin/**` — admin mutations
- `src/lib/queries.ts`, `src/lib/admin-queries.ts` — read-side data helpers
- `src/lib/payments.ts` — the M-Pesa/Card stub simulation rules
- `src/app/admin/(protected)/**` — admin back-office, guarded by a shared layout calling `requireAdmin()`
- `src/app/learn/[slug]` — the learner course-consumption experience

## Known scope trims (disclosed, not oversights)

- **Lesson-level video** is URL-based only in the admin editor (course
  thumbnail and course-level preview video support file upload; individual
  lesson videos pick from the placeholder pool or a pasted URL). A per-lesson
  upload field is a straightforward addition if needed.
- **Curriculum drag-reorder** uses `@dnd-kit` for modules; lessons within a
  module reorder via up/down buttons rather than nested drag-and-drop,
  which is meaningfully more complex to get right across two levels.
- **Google sign-in** is a genuine stub per spec: one click creates/logs into
  a fixed demo account (`google.demo@example.com`), no OAuth flow.
- File uploads (avatars, thumbnails, certificate backgrounds) land on local
  disk under `public/uploads/runtime/` behind `src/lib/storage.ts` — swap
  that one file for an S3/R2 client to go real.

## Acceptance walkthrough (spec-2.md §11)

1. Guest → homepage → `/courses` (filter/search) → course detail → play a
   free-preview lesson, no sign-in required.
2. `/signup` → account created, verification email stubbed (see
   `/admin/notifications`) → `/verify-email?token=...` marks it verified.
3. Free course → "Enroll free" → straight to `/learn/[slug]`.
4. Paid course → `/checkout/[slug]` → both M-Pesa and Card, including the
   failure/pending triggers above.
5. `/learn/[slug]` → video (resumes from last position), reading, and quiz
   lessons; progress persists across reloads/sessions.
6. Finish every lesson in a short course → certificate auto-issued →
   `/certificates/[id]` → "Download PDF" → `/verify/[id]` confirms it
   publicly.
7. `/admin/courses/new` → fill Basics → Media → Curriculum (add a module,
   lessons, a quiz) → Pricing → Publish → appears on `/courses` immediately.
8. `/admin` → students/enrollments/payments/charts, all populated from seed
   data.
9. `/admin/coupons` → create one → apply it at `/checkout/[slug]`.
10. Resize down to 360px — filter drawers, sticky enroll bar, and the admin
    shell's mobile nav all adapt.
11. All payment/email/SMS interactions are stubs — verified by design (see
    `src/lib/payments.ts`, `src/lib/notify.ts`).
12. `npm run db:seed` — deterministic, idempotent (clears and repopulates).

## Deployment

This branch (`v2-ecommerce`) has not been merged to `main` or deployed —
`main` still serves the v1 marketing demo on Vercel. SQLite-on-disk needs a
persistent volume or a hosted SQLite (e.g. Turso) to survive redeploys on
Vercel's ephemeral filesystem; swapping `DATABASE_URL` and the driver
adapter in `src/lib/db.ts` is the only change needed since everything else
goes through Prisma.
