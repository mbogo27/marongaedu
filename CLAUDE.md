# Dental Academy: Full LMS (v2)

Full-stack build of `SPEC-v2-full-lms.md` (supersedes `spec-2.md`). Real accounts, email, storage, server-side checkout and certificates; **only payment rails are simulated** (behind the `PaymentProvider` interface). README.md has setup, demo credentials and deployment; docs/ has ARCHITECTURE, DECISIONS (why things are the way they are), GAP (requirement status) and WALKTHROUGH. Read the relevant Next.js guide in `node_modules/next/dist/docs/` before changing framework-level code.

Stack: Next.js 16 (App Router, Turbopack), TypeScript, Tailwind v4, **PostgreSQL + Prisma 7** (`@prisma/adapter-pg`), custom session auth, TipTap, dnd-kit, Recharts, pdf-lib, Vitest, Playwright.

## Conventions you must keep

- **Every protected action re-checks auth server-side** via `src/lib/dal.ts` (`requireUser`, `requireVerifiedUser`, `requireAdmin` → 404, `getCourseAccess`, `getAdminOrNull` for route handlers). UI hiding and `src/proxy.ts` are conveniences, never the check. Lesson content goes **only** through `getLessonView` (`src/lib/lesson-access.ts`).
- **`src/proxy.ts` must stay inside `src/`** (the project uses a `src` dir; a root `proxy.ts` is silently ignored). It sets the nonce CSP and does optimistic redirects.
- **Adapters, not providers:** email (`src/lib/email`), storage (`src/lib/storage`), payments (`src/lib/payments`), rate limiting (`src/lib/rate-limit.ts`), analytics. Add providers behind the interface; do not call vendor SDKs from features.
- **Prices are computed on the server** (`quoteCourse`/`startCheckout`). Never accept an amount from the client. Money is integer KES.
- **Rich text is sanitised** with `sanitizeRichText` on write *and* render.
- **Server action files (`"use server"`) export only async functions.** Helpers that take a user id (e.g. `anonymiseUser`) live in non-action modules so they cannot be invoked from the browser.
- **Course editor saves by id** (`src/lib/admin/course-service.ts`). Never switch it to delete-and-recreate: that destroys learner progress.
- Tokens (verify/reset/invite/session) are stored **hashed**; consume them with `consumeToken` (atomic, single-use).
- Strings in auth/account/checkout/learning flows go through `t()` (`src/lib/i18n`).

## Commands

`npm run dev|build|start` · `typecheck` · `lint` · `test` (Vitest, needs Postgres at `TEST_DATABASE_URL`) · `test:e2e` (Playwright, build first; uses branded Chrome for H.264) · `db:migrate|deploy|seed|reset` · `admin:create`. Scripts that import app code run under `tsx --conditions=react-server` so `server-only` resolves.

## Gotchas

- A Client Component must not import a module that touches the DB (`db`, `getSetting`, …). Pass data down from a Server Component.
- The footer newsletter form adds a second "Email address" field to most pages: use `getByLabel("Email address", { exact: true })` or scope to `main` in tests.
- `Intl.NumberFormat("en-KE")` renders KES as "Ksh 8,500" (tests accept both).
- Card simulator triggers need **Luhn-valid** numbers ending `0000` / `0002` (see README).
- Prisma 7: connection config lives in `prisma.config.ts` (CLI) and `src/lib/db.ts` (adapter); `createMany` does not accept `skipDuplicates` on every provider, avoid it.
- Typed route params: `RouteContext<'/path/[param]'>` is generated by `next typegen` / dev / build.
- Local dev Postgres in this repo's author environment runs on port 5433 (`maronga`, `maronga_test`, `maronga_e2e` databases); the committed defaults use 5432 (docker-compose).
